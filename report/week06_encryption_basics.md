### 자료보호와 암호화 기술의 원리

### 해싱/ 대칭/ 비대칭 암호화 알고리즘 정리

> 🔐`암호와 기술의 핵심 원리:` 암호화 기술은 크게 **기밀성 (Confidentiality)**, **무결성 (Integrity)**, **인증 (Authentication)**, **부인 방지 (Non-repudiation)** 의 4가지 핵심 목표를 달성하기 위해 사용됩니다.

- **기밀성:** 인가되지 않은 사용자가 정보의 내용을 알 수 없도록 합니다.
  > 🧩(예: 메시지를 암호화하여 제3자가 읽을 수 없게 함)
- **무결성:** 허락되지 않은 사용자가 정보를 함부로 변경할 수 없도록 합니다.
  > 🧩(예: 데이터가 전송 중 변조되지 않았는지 확인)
- **인증:** 사용자 또는 객체의 디지털 정체성을 식별합니다.
  > 🧩(예: 사용자가 본인임을 확인)
- **부인 방지:** 정보를 보낸 사람이 나중에 자신이 정보를 보냈다는 사실을 부인하지 못하도록 합니다.
  > 🧩(예: 디지털 서명을 통해 송신자의 행위를 증명)

1. **해싱(Hashing) 알고리즘**
   > ✅해싱은 데이터를 단방향으로 변환하는 암호화 기술입니다. 즉, 원본 데이터를 특정 알고리즘을 통해 고정된 길이의 해시 값 (Hash Value) 또는 해시 코드로 변환하지만, 이 해시 값으로는 원본 데이터를 역으로 복원할 수 없습니다. 이는 마치 지문을 찍는 것과 유사합니다.
   > ![alt text](https://encrypted-tbn2.gstatic.com/licensed-image?q=tbn:ANd9GcTi4XXm19vDKLTkj4QSDonCM4qviLaCxs_Ei-ge8bqm17PNiPljjMzTKjeiMW3Vd9bovKNtGdKQ32Oq1_gIS9ty0OoDN1rhb_9GQr8qgtWHH7LpmZs)

- **작동 원리**

  - **입력:** 어떤 길이의 원본 데이터 (텍스트, 파일 등)이 해시 함수에 입력됩니다.
  - **해시 함수 적용:** 해시 함수는 이 데이터를 고유한 수학적 연산을 통해 처리합니다.
  - **출력:** 고정된 길이의 해시 값이 생성됩니다.
    > 🧩예를 들어, SHA-256 (Secure Hash Algorithm 256) 알고리즘은 입력 데이터의 크기와 상관없이 항상 256비트 길이의 해시 값을 출력합니다.

- **주요 특징**

  - **단방향성 (One-wayness):** 해시 값에서 원본 데이터를 복원하는 것이 사실상 불가능합니다.
  - **결정론적 (Deterministic):** 동일한 입력에 대해서는 항상 동일한 해시 값을 출력합니다. 단 1비트라도 입력값이 달라지면 전혀 다른 해시 값이 나옵니다. 이를 **눈사태 효과 (Avalanche Effect)** 라고 합니다.
  - **충돌 저항성 (Collision Resistance):** 서로 다른 두 입력이 동일한 해시 값을 생성할 확률이 매우 낮아야 합니다.
    > 🧩완벽하게 0은 아니지만, 사실상 불가능에 가깝습니다.

- **활용 예시**

  - **데이터 무결성 검증:** 파일 다운로드 시, 다운로드된 파일의 해시 값을 계산하여 원본 파일의 해시 값과 비교합니다. 두 값이 같으면 파일이 전송 중 변조되지 않았음을 의미합니다.
  - **비밀번호 저장:** 사용자 비밀번호를 그대로 저장하지 않고, 비밀번호의 해시 값을 데이터베이스에 저장합니다. 로그인 시 입력된 비밀번호의 해시 값을 계산하여 저장된 해시 값과 비교하여 인증합니다. 만약 데이터베이스가 유출되어도 해시 값만으로는 원본 비밀번호를 알기 어렵습니다.
  - **디지털 서명:** 메시지의 무결성을 보장하고 송신자를 인증하는 데 사용됩니다.

2. **대칭(Symmetric) 암호화**
   > ✅**대칭 암호화**는 암호화와 복호화에 동일한 비밀 키 (Secret Key)를 사용하는 방식입니다. 마치 잠긴 상자를 같은 열쇠로 열고 닫는 것과 같습니다.
   > ![alt text](https://blog.kakaocdn.net/dna/bHAffK/btrkAuVQeRt/AAAAAAAAAAAAAAAAAAAAAJV_qMg1eT-wE-Ye3viXHEhidPP3F8ESkq7n-c3TqFfP/img.png?credential=yqXZFxpELC7KVnFOS48ylbz2pIh7yKj8&expires=1753973999&allow_ip=&allow_referer=&signature=5uYMuWqeI0RMA6Ze8SuIewgAwok%3D)

- **작동 원리**

  - **키 생성:** 송신자와 수신자가 공유할 단 하나의 비밀 키를 생성합니다. 이 키는 안전하게 관리되어야 합니다.
  - **암호화:** 송신자는 **평문 (Plaintext)** 이라고 불리는 원본 데이터를 비밀 키와 암호화 알고리즘을 사용하여 **암호문 (Ciphertext)** 으로 변환합니다.
  - **전송:** 암호문을 수신자에게 전송합니다.
  - **복호화:** 수신자는 동일한 비밀 키와 복호화 알고리즘을 사용하여 암호문을 평문으로 다시 변환합니다.

- **주요 특징**

  - **빠른 속도:** 대칭화는 비대칭 암호화에 비해 연산 속도가 빠르고 효율적입니다. 대량의 데이터를 암호화하고 복호화하는 데 적합합니다.
  - **단일 키:** 암호화와 복호화에 동일한 키를 사용하기 때문에 키 관리가 비교적 간단합니다.

- **대표적인 알고리즘**
  - **AES(Advanced Encryption Standard):** 현재 가장 널리 사용되는 대칭 암호화 알고리즘입니다. 높은 보안성과 효율성을 제공하여 대부분의 보안 시스템에서 표준으로 채택되고 있습니다.
  - **DES(Data Encryption Standard) / 3DES (Triple DES):** AES 이전에 사용되던 알고리즘으로, 현재는 보안 취약점 때문에 거의 사용되지 않습니다. 3DES는 DES의 보안 문제를 개선한 버전이지만, AES보다 느립니다.
  - **SEED, ARIA:** 한국에서 개발된 대칭 암호화 알고리즘입니다.

3. **비대칭(Asymmetric) 암호화와 알고리즘**
   > ✅**비대칭 암호화**는 **한 쌍의 서로 다른 키 (공개 키와 개인 키)** 를 사용하는 암호화 방식입니다. 공개 키는 누구에게나 공개되어도 상관없지만, 개인 키는 소유자만 비밀리에 보관해야 합니다.
   > ![alt text](https://encrypted-tbn0.gstatic.com/licensed-image?q=tbn:ANd9GcSCIpphjQ-RTJKgBF8_tgnTWGulJWiVgXH3X8y4t6Xtv-BvrjlGxrK6P5D-OdXSuIn6-zvVrBoi9rJkfeM8qO2Yr9QEyHIPHGw3lVEvPFBxRqetSJM)

- **작동 원리**

  - **키 생성:** 각 사용자는 서로 수학적으로 연관된 공개 키와 개인 키 한 쌍을 생성합니다.
  - **공개 키 배포:** 사용자는 자신의 **공개 키 (Public Key)** 를 다른 사람들에게 공개적으로 배포합니다.
  - **암호화:** 송신자는 수신자의 **공개 키**를 사용하여 메시지를 암호화합니다.
  - **전송:** 암호화된 메시지는 수신자에게 전송됩니다.
  - **복호화:** 수신자는 자신의 **개인 키 (Private Key)** 를 사용하여 암호문을 복호화합니다. 중요한 것은 수신자의 개인 키 외에는 누구도 해당 암호문을 복호화할 수 없다는 점입니다.
  - **디지털 서명 (인증 및 부인 방지 목적):** 송신자는 자신의 **개인 키**를 사용하여 메시지를 서명 (암호화)하고, 수신자는 송신자의 **공개 키**를 사용하여 서명을 검증합니다. 이를 통해 메시지가 송신자에 의해 작성되었음을 확인하고, 송신자가 나중에 자신의 행위를 부인하는 것을 방지할 수 있습니다.

- **대표적인 알고리즘**

  - **RSA (Rivest-Shamir-Adleman):** 가장 널리 사용되는 비대칭 암호화 알고리즘입니다. 주로 **보안 통신 (HTTPS)**, **디지털 서명**, **키 교환** 등에 사용됩니다.
  - **ECC (Elliptic Curve Cryptography):** RSA보다 짧은 키 길이로도 동일한 수준의 보안 강도를 제공하여 모바일 환경 등 자원 제약적인 환경에서 활용도가 높습니다.

- **해싱, 대칭, 비대칭 암호화 비교**

| 특징      | `해싱(Hashing)`                   | `대칭 암호화(Symmetric Encryption)` | `비대칭 암호화(Asymmetric Encryption)`         |
| --------- | --------------------------------- | ----------------------------------- | ---------------------------------------------- |
| 방향성    | 단방향(복원 불가능)               | 양방향(복호화 가능)                 | 양방향(복호화 가능)                            |
| 키 개수   | 키 없음(알고리즘 자체 사용)       | 1개(비밀 키)                        | 2개(공개 키, 개인 키)                          |
| 속도      | 매우 빠름                         | 빠름                                | 느림                                           |
| 주요 목적 | 데이터 무결성 검증, 비밀번호 저장 | 데이터 기밀성 유지 (대용량)         | 기밀성, 인증, 부인 방지 (키 교환, 디지털 서명) |
| 키 분배   | 해당 없음                         | 안전한 키 분배 필요                 | 공개 키는 공개, 개인 키는 비밀 유지            |
| 예시      | SHA-256, MD5                      | AES, DES, SEED, ARIA                | RSA, ECC                                       |
